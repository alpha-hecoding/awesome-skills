# 开篇模式库

本文档定义微信公众号文章的开篇引入模式,确保文章开头具有统一的风格和吸引力。

## 核心开篇模式

### 模式1: 痛点场景引入(最常用)

```markdown
你有没有遇到过这种情况?

[痛点1描述,具体场景]

[痛点2描述,具体场景]

[痛点3描述,具体场景]

说实话,我之前也是这样。

直到我发现了一个[解决方案/方法/工具]——**[主题]**。
```

**使用场景**: 适用于大多数技术文章,特别是工具介绍、问题解决方案类文章。

**示例**:
```markdown
你有没有遇到过这种情况?

用Claude Code写代码时,它说"我无法访问你的数据库"。

想让它帮你分析Sentry的错误日志,它却说"我看不到你的数据"。

想让它帮你创建GitHub PR,它又告诉你"我没有权限"。

说实话,我之前也是这样。

直到我发现了一个神奇的东西——**MCP**。
```

### 模式2: 对比式引入

```markdown
[旧方式的痛点描述,2-3句]

说实话,我之前也是这样。

[新方式的优势描述,1-2句]

今天就来聊聊,[主题]是怎么一回事。
```

**使用场景**: 适用于对比、优化、升级类文章。

**示例**:
```markdown
传统的AI助手,只能通过你"中转"来操作工具——你得复制粘贴,手动执行。

说实话,我之前也是这样。

而MCP让AI直接接入你的工具链,像你一样使用Git、查询数据库、分析日志。

今天就来聊聊,这个让Claude Code如虎添翼的MCP到底是怎么一回事。
```

### 模式3: 提问式引入

```markdown
[问题1]?

[问题2]?

[问题3]?

如果答案是肯定的,那你一定需要了解——**[主题]**。
```

**使用场景**: 适用于功能介绍、新特性发布类文章。

**示例**:
```markdown
想让AI助手同时服务多个平台?

希望用户在哪都能找到你的AI?

想要一次开发,多端部署?

如果答案是肯定的,那你一定需要了解——**OpenClaw.AI**。
```

### 模式4: 故事式引入

```markdown
[场景描述,1-2句]

[问题出现]

[尝试解决的过程]

最后发现,原来[主题]可以完美解决。
```

**使用场景**: 适用于案例分析、经验分享类文章。

**示例**:
```markdown
上周,我接到了一个紧急任务——把公司的AI客服部署到WhatsApp、Telegram和Discord三个平台。

我原本打算为每个平台单独开发接口,但估算了一下,至少需要两周时间。

而且后续维护三个系统,想想就头大。

最后发现,原来OpenClaw.AI可以一个网关搞定所有平台。
```

## 开篇要素清单

一个优秀的开篇应包含:

- [ ] **痛点共鸣**: 读者能产生"我也是这样"的感觉
- [ ] **口语化表达**: 使用"说实话"、"你有没有"等口语词汇
- [ ] **具体场景**: 不是抽象描述,而是具体的使用场景
- [ ] **情绪连接**: 第一人称叙述,建立情感联系
- [ ] **解决方案预告**: 引出主题,激发阅读兴趣
- [ ] **简洁有力**: 开篇不超过150字

## 开篇注意事项

### 要做的:
✅ 用具体场景代替抽象描述
✅ 使用第一人称"我"
✅ 包含"说实话"等口语化表达
✅ 列举2-3个痛点(不过多也不过少)
✅ 痛点要真实可信,能引起共鸣

### 不要做的:
❌ 开篇过长(超过150字)
❌ 使用太多专业术语
❌ 没有痛点直接开始介绍
❌ 痛点过于抽象或不真实
❌ 痛点超过5个(会让读者失去耐心)

## 选择指南

根据文章类型选择开篇模式:

| 文章类型 | 推荐开篇模式 | 原因 |
|---------|------------|------|
| 工具介绍 | 痛点场景引入 | 直接展示使用痛点 |
| 问题解决 | 痛点场景引入 | 问题导向明确 |
| 对比分析 | 对比式引入 | 强调差异 |
| 新功能发布 | 提问式引入 | 激发兴趣 |
| 案例分享 | 故事式引入 | 情境代入 |
| 教程指南 | 痛点场景引入 | 明确学习价值 |

## 开篇词库

以下词汇可灵活运用:

**开场词**:
- 你有没有遇到过这种情况?
- 说实话,我之前也是这样。
- 想象一下...
- 记得有一次...

**转折词**:
- 直到我发现...
- 后来我才知道...
- 原来可以用...
- 这让我意识到...

**引入词**:
- 今天就来聊聊...
- 这就是我要介绍的...
- 接下来,让我带你了解...
- 我们一起来看看...
