# 语言风格规则库

本文档定义微信公众号文章的语言风格规则,确保文章具有统一的口语化、亲和力强的表达风格。

## 核心风格原则

### 原则1: 口语化优先

**规则**: 使用口语化表达,避免过于正式的书面语。

**要做的**:
- ✅ 使用"说实话"、"简单来说"、"其实"等口语词汇
- ✅ 使用"你有没有"、"是不是"等互动性表达
- ✅ 使用短句,每句不超过30字
- ✅ 使用第一人称"我"、"我们"

**不要做的**:
- ❌ 使用过于正式的表达,如"鉴于"、"基于此"
- ❌ 使用长句,超过40字
- ❌ 使用生僻词汇或专业术语过多

**对比示例**:
```
❌ 鉴于上述原因,该工具具有显著的优势,能够显著提升开发效率。

✅ 说实话,这个工具真的很好用,能让你的开发效率提升一大截。
```

### 原则2: 第一人称叙述

**规则**: 使用第一人称"我"或"我们",建立情感连接。

**要做的**:
- ✅ "我发现"、"我之前"、"我遇到的"
- ✅ "我试过"、"我研究过"、"我总结了一下"
- ✅ "说实话,我之前也是这样"

**不要做的**:
- ❌ 使用第三人称或客观描述
- ❌ "作者认为"、"笔者认为"

**对比示例**:
```
❌ 该工具在开发中具有重要作用。

✅ 我发现这个工具在开发中真的很好用。
```

### 原则3: 大量使用比喻和类比

**规则**: 用日常生活中的事物比喻技术概念,降低理解门槛。

**比喻模式**:
- `就像...`
- `好比...`
- `这就像...`
- `可以把它想象成...`

**比喻示例**:
- MCP就像是AI世界的"USB接口"
- Hooks就像是AI助手生命周期中的"检查点"
- 这就像你有一把万能钥匙,能打开所有房间的门
- 就像给AI装上了无数条"手臂"

**比喻清单**:
- USB接口 → 通用连接
- 翻译官 → 协议转换
- 万能钥匙 → 多场景适用
- 助手/管家 → 自动化工具
- 检查点/关卡 → 流程控制
- 手臂 → 扩展能力
- 杠杆 → 效率提升工具

### 原则4: 反问句和疑问句

**规则**: 多用反问句和疑问句,增强互动性和代入感。

**常用反问句式**:
- 你有没有遇到过这种情况?
- 是不是很麻烦?
- 怎么办呢?
- 有没有办法解决?
- 是不是听起来很复杂?

**常用疑问句式**:
- 什么是...?
- 怎么使用...?
- 有什么好处?
- 为什么要...?
- 如何解决...?

### 原则5: 适当使用表情符号

**规则**: 适当使用表情符号增加亲和力,但不过度。

**使用场景**:
- ✅ 列表项前: ✅、❌、🔧、💡、🔍、⚠️
- ✅ 结尾号召: 👇、💬
- ✅ 强调重点: ⭐、👉

**使用原则**:
- 每段不超过2个表情符号
- 表情符号要与内容相关
- 正式技术内容少用,轻松话题多用

**表情符号映射**:
| 类型 | 符号 | 使用场景 |
|-----|------|---------|
| 成功/正确 | ✅ | 完成的步骤、正确的做法 |
| 失败/错误 | ❌ | 错误的做法、失败的案例 |
| 工具 | 🔧 | 工具介绍、配置操作 |
| 思考 | 💡 | 重要提示、关键点 |
| 搜索 | 🔍 | 查找、搜索相关 |
| 警告 | ⚠️ | 注意事项、风险提示 |
| 星标 | ⭐ | 重点强调 |
| 指向 | 👉 | 引导注意 |
| 互动 | 💬 | 评论区互动 |
| 指引 | 👇 | 点击、查看 |

## 语言风格检查清单

写完一段后,检查:

- [ ] 是否包含"说实话"、"其实"等口语词汇?
- [ ] 是否使用第一人称"我"?
- [ ] 是否包含比喻或类比?
- [ ] 是否使用反问句或疑问句?
- [ ] 句子是否简短(不超过30字)?
- [ ] 表情符号使用是否恰当(每段不超过2个)?
- [ ] 是否避免使用过于正式的表达?

## 句式模式

### 模式1: 痛点描述句式
```
你有没有遇到过这种情况?

[具体场景] + [问题] + [困扰程度]
```

示例:
```
你有没有遇到过这种情况?

每次部署都要重复配置,至少花费半小时,让人头疼不已。
```

### 模式2: 解决方案句式
```
直到我发现了一个[方法/工具]——[名称]。

[简单描述]。
```

示例:
```
直到我发现了一个神奇的工具——OpenClaw.AI。

一个网关,就能连接所有平台。
```

### 模式3: 比喻说明句式
```
[概念]就像是[喻体]。

[详细说明]。
```

示例:
```
MCP就像是AI世界的"USB接口"。

就像你用USB接口连接鼠标、键盘、打印机一样,MCP让Claude Code能连接到数百个外部工具。
```

### 模式4: 对比强调句式
```
以前的做法:[旧方法,2-3句]

现在的做法:[新方法,2-3句]

[效果对比]。
```

示例:
```
以前的做法:为每个平台单独开发机器人,维护成本高。

现在的做法:一次部署,所有平台自动连接。

开发时间从几周缩短到几天。
```

### 模式5: 价值总结句式
```
[主题]的核心价值就是[一句话总结]。

[展开说明,1-2句]。
```

示例:
```
OpenClaw.AI的核心价值就是一次部署,多端使用。

让AI助手真正实现"用户在哪里,服务就在哪里"。
```

## 风格一致性的写作流程

1. **开头**: 使用痛点引入模式,包含"说实话,我之前也是这样"
2. **主体**:
   - 每段开始使用口语化过渡
   - 至少使用3个比喻或类比
   - 适当穿插反问句和疑问句
   - 每段控制表情符号数量
3. **结尾**: 总结价值 + 金句 + 互动

## 常见风格问题及解决

### 问题1: 过于正式

**表现**: "鉴于"、"基于此"、"综上所述"

**解决**: 替换为口语化表达
- "鉴于" → "考虑到" 或 "因为"
- "基于此" → "所以" 或 "基于这点"
- "综上所述" → "总的来说"

### 问题2: 句子过长

**表现**: 一个句子超过40字,包含多个分句

**解决**: 拆分为多个短句
```
❌ 该工具通过智能算法自动分析代码质量并提供优化建议,能够显著提升开发效率和代码可维护性。

✅ 这个工具能自动分析代码质量,给出优化建议。
✅ 用它来提升开发效率,真的很方便。
```

### 问题3: 缺少比喻

**表现**: 技术概念描述过于抽象

**解决**: 添加生活化比喻
```
❌ MCP是一种模型上下文协议,用于连接AI和外部工具。

✅ MCP就像是AI世界的"USB接口",让AI能连接到各种外部工具,就像电脑通过USB连接鼠标和键盘一样。
```

## 示例段落对比

### 正式风格 vs 口语化风格

**正式风格**:
```
该系统采用模块化架构设计,支持多种消息协议的接入与转换,具备良好的扩展性和可维护性。通过统一的API接口,开发者可以快速集成各类即时通讯平台,实现消息的跨平台分发与管理。
```

**口语化风格**:
```
这个系统设计得很聪明——模块化的架构让它可以轻松接入各种消息平台。

就像一个万能翻译官,把你的AI助手翻译成各种平台能听懂的语言。

开发者只需要关注AI本身的能力,剩下的事情交给系统处理就行了。
```

关键差异:
- "采用模块化架构设计" → "设计得很聪明——模块化的架构"
- "支持多种消息协议的接入与转换" → "就像一个万能翻译官"
- "具备良好的扩展性和可维护性" → (省略,用比喻替代)
- "通过统一的API接口" → "只需要关注AI本身的能力"

记住:**好的技术写作,不是展示你的专业程度,而是让读者理解并愿意尝试。**
