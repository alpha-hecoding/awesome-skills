# 指南型文章结构模板

本文档定义指南型(Guide)文章的标准结构,适用于全面系统地介绍某个主题的文章。

## 文章类型说明

**指南型文章特点**:
- 全面系统地介绍主题
- 分多个方面深入讲解
- 适合有一定复杂度的主题
- 读者通过文章能全面了解主题

**适用场景**:
- 工具/框架全面介绍
- 技术方案指南
- 最佳实践总结
- 系统性知识讲解

## 详细说明

### 1. 开篇引入(必须使用痛点场景)

**模板**:
```markdown

[痛点1: 具体场景描述]

[痛点2: 具体场景描述]

[痛点3: 具体场景描述]

说实话,我之前也是这样。

直到我发现了一个[解决方案]——**[主题]**。

[一句话说明核心价值]。
```

**示例**:
```markdown
你有没有遇到过这种情况?

```

### 2. 概念介绍部分

**标题**: "什么是[X]?" 或 "[X]是什么?"

**内容要求**:
- 用一句话定义概念
- 用比喻说明(类比日常生活事物)
- 说明核心价值

**模板**:
```markdown
## 什么是[X]?

[X]是[一句话定义]。

它的核心功能就像一个**[比喻对象]**,[比喻说明]。

你只需要[用户要做什么],剩下的事情交给[X]。
```

**示例**:
```markdown
## 它到底是什么?

OpenClaw.AI是一个开源的AI多平台部署框架。

它的核心功能就像一个**万能翻译器**,把你的AI助手翻译成各种平台能听懂的语言。

你只需要关注AI本身的能力,剩下的事情交给OpenClaw.AI。

就好比你想向世界各地的朋友分享一个故事,你不需要学会每种语言,只需要一个翻译官就够了。

OpenClaw.AI就是这个翻译官。
```

### 3. 特性介绍部分

**标题**: "[X]有什么厉害之处?" 或 "它有什么优势?"

**内容要求**:
- 分3-5个特性讲解
- 每个特性有: 标题、说明、实例/代码
- 使用H3标题分隔每个特性

**模板**:
```markdown
## [X]有什么厉害之处?

### 1. [特性名称]

[特性说明,2-3句]

[实例/代码示例]

**适用场景**: [说明适合什么场景]
```

**示例**:
```markdown
## 它有什么厉害之处?

### 1. 多平台一键连接

最让人眼前一亮的是它的**多渠道支持**。

你可以通过一个Gateway网关,同时接入:

- WhatsApp(最主流的即时通讯工具)
- Telegram(开发者和极客的最爱)
- Discord(游戏和社区交流的首选)
- iMessage(苹果生态的标配)

不需要为每个平台单独开发,一次配置,全部搞定。

这就好比你有一把万能钥匙,能打开所有房间的门。

不用再为每扇门配一把钥匙,省时又省力。
```

### 4. 使用方法部分

**标题**: "怎么使用[X]?" 或 "如何开始?"

**内容要求**:
- 分步骤或分方式讲解
- 每个步骤有详细说明和代码示例
- 使用H3标题分隔

**模板**:
```markdown
## 怎么使用[X]?

### 方式一:[方式名称]

[说明,2-3句]

```[language]
[代码示例]
```

**适用场景**: [说明适合什么场景]
```

**示例**:
```markdown
## 三种连接方式,总有一种适合你

MCP支持三种连接方式,不管你是个人开发者还是团队协作,都能找到合适的方案。

### 方式一:HTTP服务器(推荐)

这是最常用的方式,适合连接云服务。

```bash
# 基本语法
claude mcp add --transport http <name> <url>

# 连接Notion
claude mcp add --transport http notion https://mcp.notion.com/mcp
```

**适用场景**:连接Notion、GitHub、Sentry等云端服务。
```

### 5. 实战案例部分

**标题**: "实战案例" 或 "实际应用"

**内容要求**:
- 2-3个真实场景案例
- 每个案例有: 背景、问题、解决方案、效果
- 使用H3标题分隔

**模板**:
```markdown
## 实战案例

### 案例一:[场景名称]

**背景**: [背景描述]

**问题**: [遇到的问题]

**解决方案**:

```[language]
[代码或配置]
```

**效果**: [实施后的效果]
```

```markdown

**MCP解决方案**:

```

**效果**:不用登录Sentry,直接在Claude里就能分析和查询错误日志。
```

## 章节安排原则

### 章节数量
- 最少: 5个主要章节(概念+特性+使用+案例+结尾)
- 最多: 8个主要章节
- 推荐: 6-7个主要章节

### 章节顺序
1. 概念介绍 (必须)
2. 特性/功能 (必须)
3. 使用方法 (必须)
4. 实战案例 (推荐)
5. 适用人群 (可选)
6. 注意事项 (可选)
7. 结尾总结 (必须)

### 章节长度
- 开篇: 100-150字
- 概念介绍: 150-200字
- 特性介绍: 每个特性100-150字,总共400-600字
- 使用方法: 每个步骤100-150字,总共300-500字
- 实战案例: 每个案例100-150字,总共200-400字
- 适用人群: 每个角色50-100字,总共150-300字
- 结尾: 100-150字

**总长度**: 3000-5000字(medium长度)

## 质量检查清单

完成文章后,检查:

- [ ] 开篇使用痛点引入模式
- [ ] 包含"说实话"等口语化表达
- [ ] 概念部分有比喻说明
- [ ] 特性部分分3-5点讲解
- [ ] 使用方法有代码示例
- [ ] 实战案例真实可信
- [ ] 适用人群分角色说明
- [ ] 结尾有金句和互动
- [ ] 使用H2标题分隔主要章节
- [ ] 每段包含口语化表达
- [ ] 至少3个比喻/类比
- [ ] 表情符号使用恰当
- [ ] 风格一致

## 注意事项

1. **不要**在指南型文章中写成教程的步骤式风格
2. **不要**省略实战案例,这会让文章缺乏说服力
3. **不要**特性介绍过多,3-5个核心特性即可
4. **要**用比喻说明概念,降低理解门槛
5. **要**提供可操作的代码示例
6. **要**覆盖不同角色/场景的适用性
