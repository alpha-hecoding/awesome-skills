技巧一：键盘快捷键，让手指飞起来

第一个要讲的，也是我最想安利给你的——键盘快捷键。

你想想，每次操作都要用鼠标点来点去，多累啊。

而快捷键就像开车时的换挡，熟悉之后根本不需要思考。

必须记住的5个生存快捷键

这些快捷键能救你于水火，建议刻在脑门上：

Ctrl+C - 取消当前输入或生成

这个我用得最多。有时候问题输入错了，或者不想等Claude回答了，直接按Ctrl+C，瞬间解脱。

就像按下了紧急停车键，随时叫停。

Ctrl+D - 退出Claude Code会话

干完活直接走人，不用繁琐的退出流程。

一个键，优雅退场。

Ctrl+R - 反向搜索命令历史

这个绝对是神器。

记不清之前用了什么命令？

按Ctrl+R，输入几个关键词，就能找到之前用过的所有相关命令。

搜索词会在匹配结果中高亮显示，一眼就能看到。

按Tab或Esc接受匹配，按Enter直接执行。

就像给命令历史装了搜索引擎，比翻记录快100倍。

快捷键速查表

Ctrl+L - 清除终端屏幕

对话多了，屏幕上乱七八糟的，看着就烦。

按Ctrl+L，一键清屏。

就像整理办公桌，瞬间清爽。

但注意，它只是清除显示，对话历史还在。

Ctrl+G - 在默认文本编辑器中打开

这个很有意思。

有时候你的提示词太长，在终端里编辑不方便。

按Ctrl+G，就会打开你的默认编辑器，在那儿编辑更顺手。

就像给对话开了个分屏，想怎么改就怎么改。

macOS用户的小陷阱

如果你用macOS，有个坑要注意。

Option/Alt键的快捷键需要特殊配置，否则可能不工作。

比如Alt+B、Alt+F、Alt+Y这些。

iTerm2：设置 → 配置文件 → 键 → 将左/右 Option 键设置为"Esc+"

Terminal.app：设置 → 配置文件 → 键盘 → 勾选"使用 Option 作为 Meta 键"

VS Code：设置 → 配置文件 → 键 → 将左/右 Option 键设置为"Esc+"

配置好了，这些快捷键才能正常工作。

我第一次用就踩了这个坑，折腾了半小时才发现。

希望你别像我一样。

技巧二：多行输入，告别复制粘贴

这个功能，是我使用频率第二高的。

为什么要多行输入？

想想看，你遇到过这些情况吗？

  • 代码太长，一行写不完，只能复制粘贴好几段
  • 想输入多段逻辑，每段都重新问一次Claude
  • 需要输入JSON、配置文件这种多行结构

传统做法，要么一次只发一段，要么用编辑器写好了复制粘贴。

都挺麻烦的。

Claude Code支持多行输入，直接解决这些问题。

三种多行输入方法

方法一：Option+Enter（macOS默认）

这是macOS上最常用的方法。

按住Option键，再按Enter，就能换行输入。

一行接一行，想写多少行都行。

最后单独按Enter发送。

方法二：Shift+Enter

这个在iTerm2、WezTerm、Ghostty、Kitty里开箱即用。

其他终端（VS Code、Alacritty、Zed、Warp）需要运行/terminal-setup安装绑定。

对于Windows和Linux用户，这个方法更通用。

方法三：\ + Enter（通用转义）

这个方法所有终端都支持。

先输入反斜杠\，再按Enter，就能换行。

就像在代码里写多行字符串，用\转义换行符一样。

最稳妥，但操作稍微麻烦一点。

多行输入方法示意图

实际应用场景

给你几个真实的使用场景：

场景一：输入完整代码

def calculate_fibonacci(n):
    if n <= 1:
        return n
    return calculate_fibonacci(n-1) + calculate_fibonacci(n-2)

请解释这段代码的时间复杂度，并优化它。

这样一次性发过去，Claude能理解完整上下文。

场景二：多段相关问题

第一，这段代码有什么问题？

第二，如何修复这些问题？

第三，有没有更优雅的实现方式？

多行提问，逻辑更清晰。

场景三：配置文件

{
  "name": "my-project",
  "version": "1.0.0",
  "dependencies": {
    "express": "^4.18.0"
  }
}

请帮我生成package.json并初始化项目。

直接贴配置文件，不用折腾。

技巧三：后台运行任务，告别傻等

这个功能，是我认为最被低估的。

为什么要后台运行？

你有没有遇到过这些尴尬时刻：

  • 运行webpack打包，要等3分钟，期间啥也干不了
  • 执行npm install，要下载一堆包，只能干瞪眼
  • 运行测试套件，要等好久，想干别的事又怕漏看结果

传统方式，你就只能等。

或者开多个终端，但切换来切换去也很麻烦。

Claude Code支持后台运行任务，完美解决这个问题。

后台运行怎么工作？

当你让Claude在后台运行命令时，它会：

  1. 立即返回一个任务ID给你
  2. 命令在后台继续执行
  3. 你可以继续输入新提示，不用等
  4. 随时可以查看后台任务的输出

这就像你请了个助手帮你跑腿，你自己可以继续干活。

多任务运行示意图

两种触发方式

方式一：直接让Claude在后台运行

输入提示词时明确说明：

"在后台运行npm install"

"后台执行webpack build"

Claude会自动用后台模式执行。

方式二：Ctrl+B快捷键

按Ctrl+B，可以将常规的Bash命令移到后台运行。

但注意：如果你用tmux，需要按两次Ctrl+B（因为tmux的前缀键也是Ctrl+B）。

什么命令适合后台运行？

基本上所有长时间运行的命令都适合：

  • 构建工具：webpack、vite、make
  • 包管理器：npm install、yarn install、pnpm install
  • 测试运行器：jest、pytest
  • 开发服务器：npm run dev
  • 长时间进程：docker、terraform

查看和管理后台任务

按Ctrl+T可以切换任务列表视图。

每次显示最多10个任务。

想看所有任务，直接问Claude："show me all tasks"

想清除任务，说"clear all tasks"

这些任务在上下文压缩中会持久保存，帮你保持组织。

甚至可以在会话之间共享任务列表，通过设置环境变量：

CLAUDE_CODE_TASK_LIST_ID=my-project claude

禁用后台任务

如果你不想用这个功能，可以禁用它：

设置环境变量CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1

但我不建议这么做，这个功能真的很好用。

技巧四：Vim编辑模式，键盘党的福音

如果你是Vim用户，这个功能会让你爱不释手。

Claude Code支持Vim风格的编辑，完全不需要鼠标。

为什么要用Vim模式？

  • 效率：所有操作都在键盘上完成，不需要频繁切换手
  • 习惯：如果你平时就用Vim，这会非常自然
  • 精确：光标控制更精确，修改更快捷
  • 流畅：编辑和执行无缝切换

Vim模式的基本操作

模式切换

Vim有两个核心模式：

NORMAL模式 - 用于导航和编辑命令

INSERT模式 - 用于插入文本

  • Esc - 从INSERT进入NORMAL
  • i - 在光标前插入（进入INSERT）
  • I - 在行首插入
  • a - 在光标后插入
  • A - 在行尾插入
  • o - 在下方打开新行
  • O - 在上方打开新行

光标移动（NORMAL模式）

  • h/j/k/l - 左/下/上/右移动
  • w - 下一个单词
  • e - 单词末尾
  • b - 上一个单词
  • 0 - 行首
  • $ - 行尾
  • ^ - 第一个非空白字符
  • gg - 输入开始
  • G - 输入结束

快速跳转

  • f{char} - 跳转到下一个字符出现处
  • F{char} - 跳转到上一个字符出现处
  • t{char} - 跳转到下一个字符出现处之前
  • T{char} - 跳转到上一个字符出现处之后
  • ; - 重复最后一个f/F/t/T动作
  • , - 反向重复

编辑操作

  • x - 删除字符
  • dd - 删除整行
  • D - 删除到行尾
  • dw/de/db - 删除单词
  • cc - 更改整行
  • C - 更改到行尾
  • cw/ce/cb - 更改单词
  • yy/Y - 复制整行
  • yw/ye/yb - 复制单词
  • p - 在光标后粘贴
  • P - 在光标前粘贴
  • >> - 缩进行
  • << - 取消缩进行
  • J - 连接行
  • . - 重复最后一个更改

文本对象

这是Vim最强大的功能之一，配合d/c/y使用：

  • iw/aw - 内部/周围单词
  • iW/aW - 内部/周围WORD（空格分隔）
  • i"/a" - 内部/周围双引号
  • i'/a' - 内部/周围单引号
  • i(/a( - 内部/周围括号
  • i[/a[ - 内部/周围方括号
  • i{/a{ - 内部/周围花括号

实战示例

删除引号内的内容：

输入di"，删除光标所在引号对内的内容。

更改整个函数：

输入da{，删除花括号包围的函数体并进入插入模式。

临时启用：输入/vim命令

永久配置：通过/config进入设置界面配置

技巧五：命令历史搜索，找命令不再翻烂眼

这个功能我用得最多，没有之一。

为什么要搜索历史？

你想想，这些问题你遇到过吗？

  • 记不清某个命令的具体参数了
  • 想找之前用过的某个复杂命令
  • 需要重复之前的某个操作

传统方式，用上下箭头翻历史记录。

翻几十次都找不到，心态崩了。

Ctrl+R反向搜索

按Ctrl+R激活反向历史搜索，然后：

  1. 开始搜索：输入文本搜索以前的命令
  2. 关键词高亮：搜索词会在匹配结果中高亮
  3. 循环匹配：再按Ctrl+R可以循环浏览更旧的匹配
  4. 接受匹配：
    • 按Tab或Esc接受并继续编辑
    • 按Enter接受并立即执行
  5. 取消搜索：
    • 按Ctrl+C取消并恢复原始输入
    • 在空搜索上按Backspace取消

实际应用

场景一：找之前用过的测试命令

Ctrl+R -> 输入"test" -> 找到"pytest tests/api/" -> 按Enter执行

场景二：找之前问过的复杂问题

Ctrl+R -> 输入"优化" -> 找到之前问的优化问题 -> 按Tab修改后执行

场景三：找之前用过的命令组合

Ctrl+R -> 输入"docker" -> 找到之前的docker命令 -> 按Enter执行

历史存储规则

  • 历史按工作目录存储
  • 用/clear命令清除
  • 用上/下箭头导航
  • 历史扩展（!）默认禁用

注意事项

历史记录只在当前会话有效。

关闭Claude Code，历史就清空了。

如果需要持久化历史，可以考虑：

  1. 用/export导出会话
  2. 在重要时刻记录命令

但大多数情况下，当前会话的历史就够用了。

技巧六：内置命令，瑞士军刀般的强大

Claude Code有一堆内置命令，每个都能解决特定问题。

为什么要有内置命令？

内置命令是常见操作的快捷方式。

就像瑞士军刀，每个刀都有它的用途。

不用记住复杂的组合，一个命令搞定。

核心内置命令总览

/clear - 清除对话历史

想从头开始？按这个。

但注意，会话还在，只是历史清空了。

/compact [instructions] - 压缩对话

对话太长，超出上下文限制？

用这个压缩，保留重要信息。

可以加指令指定压缩重点：

/compact 保留所有代码修改和错误信息

/config - 打开设置界面

配置Claude Code的各种选项。

模型、主题、权限等等都在这里。

/context - 可视化上下文使用情况

用彩色网格展示当前上下文占用。

快超限了？一眼就能看到。

/cost - 显示token使用统计

看看你花了多少token。

对于订阅用户，能看到详细的成本追踪。

/doctor - 检查安装健康状况

出问题了？让医生看看。

会诊断你的配置、依赖等。

/exit - 退出REPL

退出Claude Code会话。

和Ctrl+D一样效果。

/export [filename] - 导出当前对话

导出对话到文件或剪贴板。

保存重要会话很有用。

/help - 获取帮助

忘命令了？问它。

输入/可以看到完整列表。

/init - 用CLAUDE.md初始化项目

CLAUDE.md是项目记忆文件。

用这个初始化，Claude就能记住项目上下文。

/mcp - 管理MCP server连接

MCP（Model Context Protocol）服务器管理。

OAuth认证也在这里。

/memory - 编辑CLAUDE.md内存文件

修改项目的记忆内容。

让Claude记住重要信息。

/model - 选择或更改AI模型

切换不同的模型试试效果。

或者用更便宜/更快的模型。

/permissions - 查看或更新权限

权限管理。

自动接受、Plan Mode、正常模式切换。

/plan - 直接进入Plan Mode

跳过提示，直接进入计划模式。

适合复杂任务。

/rename - 重命名当前会话

给会话起个名字，方便管理。

/resume [session] - 恢复对话

按ID或名称恢复之前的会话。

或者打开会话选择器。

/rewind - 回退对话和/或代码

时光倒流，回到之前的状态。

Ctrl+Esc两次也可以。

/stats - 可视化使用情况

看看你每天用多少，用得最多的是哪个模型。

还有会话历史和连胜记录。

/status - 打开状态界面

查看版本、模型、账户、连接性。

/statusline - 设置状态行UI

自定义状态栏显示什么。

/tasks - 列出和管理后台任务

查看所有后台任务，管理它们。

/teleport - 从claude.ai恢复远程会话

仅限订阅用户。

跨设备同步会话。

/theme - 更改颜色主题

换个主题，换个心情。

/todos - 列出当前TODO项

看看有哪些待办事项。

/usage - 显示计划使用限制

仅限订阅计划。

查看配额和速率限制。

命令功能总览

快速命令前缀

除了内置命令，还有几个快速前缀：

/ 在开始 - 命令或skill

输入/加上命令名或skill名，快速调用。

! 在开始 - Bash模式

直接运行bash命令，不用通过Claude。

! npm test
! git status

输出会直接加入对话上下文。

支持历史自动完成，按Tab补全。

@ - 文件路径提及

触发文件路径自动完成。

MCP Prompts

MCP servers可以暴露prompts作为命令。

格式：/mcp____

从连接的服务器动态发现。

技巧七：任务列表，让复杂工作井井有条

处理复杂任务时，Claude会创建任务列表跟踪进度。

什么是任务列表？

任务列表出现在终端状态区域，显示：

  • 待处理的任务
  • 正在进行的任务
  • 已完成的任务

就像一个项目管理板，实时显示工作进度。

查看任务列表

按Ctrl+T切换任务列表视图。

一次最多显示10个任务。

想看所有任务，直接问Claude：

"show me all tasks"

想清除任务：

"clear all tasks"

任务列表的价值

  • 可视化进度：一目了然看到当前状态
  • 组织工作：在复杂项目中保持有序
  • 上下文持久：在上下文压缩中持续存在
  • 跨会话共享：设置环境变量可以在会话间共享

跨会话任务列表

设置环境变量：

CLAUDE_CODE_TASK_LIST_ID=my-project claude

会使用~/.claude/tasks/中的命名目录存储任务列表。

这样你可以在不同会话间共享任务状态。

实际应用场景

场景一：多步骤重构

任务1: 重构API层
任务2: 更新数据库schema
任务3: 修改前端接口
任务4: 添加测试用例

每个任务独立进行，整体进度清晰可见。

场景二：批量数据处理

任务1: 下载原始数据
任务2: 清洗和转换
任务3: 生成报告
任务4: 发送邮件

并行执行，提高效率。

场景三：持续集成

任务1: 运行单元测试
任务2: 运行集成测试
任务3: 构建Docker镜像
任务4: 部署到staging

自动化流水线，减少人为干预。

实战：把这些技巧组合起来

讲了这么多技巧，实际怎么用呢？

给你一个真实的工作流示例。

场景：重构一个API端点

步骤1：了解当前代码

输入问题，询问当前实现。

请分析/src/api/user.js中getUser函数的实现，
找出潜在问题。

步骤2：在后台运行测试

在后台运行npm test，看看当前测试通过情况。

按Ctrl+B或明确说"后台运行"。

步骤3：继续规划重构

测试在后台跑，你继续问Claude：

基于刚才的分析，给我一个重构方案，
包括代码改进和测试补充。

步骤4：用多行输入详细说明

用Option+Enter或Shift+Enter输入详细需求：

重构要求：
1. 改进错误处理
2. 添加输入验证
3. 优化数据库查询
4. 增加单元测试

请按这个顺序重构代码。

步骤5：用Vim模式快速编辑

启动Vim模式/vim。

编辑Claude生成的代码，快速调整。

步骤6：搜索之前的命令

找之前运行过的测试命令：

Ctrl+R -> 输入"test" -> 找到"npm test -- --coverage"

步骤7：创建任务列表跟踪

创建重构任务列表：
1. 重构getUser函数
2. 添加输入验证
3. 优化数据库查询
4. 补充单元测试
5. 集成测试

步骤8：按任务列表执行

用/tasks查看进度，逐个完成。

步骤9：导出会话

完成后，导出会话记录：

/export api-refactor-log.md

常见问题解答

Q：这么多快捷键，记不住怎么办？

A：不用一次全记住。

先记最常用的5个：

Ctrl+C（取消）、Ctrl+R（搜索）、Ctrl+L（清屏）、Ctrl+D（退出）、Ctrl+G（编辑）

其他的慢慢来，用多了自然就记住了。

就像学英语，先学会日常对话，再学高级词汇。

Q：Vim模式太难了，可以不用吗？

A：当然可以。

Vim模式是可选的，不是必须的。

不用Vim，你依然能高效使用Claude Code。

但如果你愿意花点时间学，回报是巨大的。

Q：后台任务会不会影响性能？

A：一般来说不会。

后台任务独立运行，不会阻塞主进程。

但如果你的机器资源有限，同时运行太多任务可能会有影响。

建议一次最多2-3个后台任务。

Q：命令历史能保存多久？

A：只在当前会话有效。

关闭Claude Code，历史就清空了。

如果需要持久化历史，用/export导出会话。

Q：哪些技巧最有用？

A：根据我的经验，这5个最有用：

  1. Ctrl+R 搜索历史 - 每天用几十次
  2. 后台运行任务 - 节省大量时间
  3. 多行输入 - 提升输入效率
  4. /compact 压缩对话 - 节省token
  5. /tasks 任务列表 - 组织复杂工作

其他技巧也很好用，但这5个是基础中的基础。

Q：Mac用户需要注意什么？

A：主要是Option键配置。

记得在终端里把Option设为Meta键：

iTerm2、Terminal.app、VS Code都要配置。

不然Alt+B、Alt+F这些快捷键不工作。

Q：可以自定义快捷键吗？

A：当前版本不支持自定义。

但Claude会根据反馈改进，未来可能会支持。

如果你有强烈需求，可以在社区反馈。
