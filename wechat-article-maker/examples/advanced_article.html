Claude Hooks：让 AI 编程助手如虎添翼的超级钩子

在 AI 编程助手的世界里，有一双看不见的手，在你每次敲击键盘时悄悄工作，它就是 Claude Hooks——让你的 AI 助手更智能、更安全、更强大。

引言：从被动响应到主动干预

想象一下，你的 AI 编程助手不仅能够响应你的指令，还能在你执行危险操作时发出警告，在代码风格不统一时自动修正，在项目启动时自动配置环境。这不是科幻，这就是 Claude Hooks 带来的现实。

Claude Hooks 是 Claude Code 插件系统中最强大的组件之一，它允许你在 AI 助手执行的每一个关键节点插入自定义逻辑，实现从被动响应到主动干预的质的飞跃。

一、Claude Hooks 核心概念

1.1 什么是 Hooks？

从本质上讲，Hooks（钩子）是一种事件驱动的编程机制。在 Claude Code 中，Hooks 就像是 AI 助手生命周期中的"检查点"，你可以定义特定的脚本或 AI 评估逻辑，在这些检查点自动执行。

核心特点：

  • 事件驱动：在特定事件发生时自动触发
  • 可编程：支持 Bash 命令和 LLM 评估两种方式
  • 多层次：可在用户、项目、插件、组件等多个层面定义
  • 并行执行：多个 Hooks 可以同时响应同一事件

1.2 Hooks 的工作原理

Claude Hooks 的工作流程可以概括为：事件触发 → 匹配器筛选 → Hooks 执行 → 结果反馈。

{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "./scripts/security-check.sh"
          }
        ]
      }
    ]
  }
}

在这个配置中，当 Claude 准备执行 Bash 工具时，会自动运行安全检查脚本，确保命令的安全性。

二、Claude Hooks 的两大执行模式

2.1 Bash 命令 Hooks：确定性规则的守护者

Bash 命令 Hooks 是最传统也最可靠的 Hooks 类型，通过执行本地脚本来实现确定性的逻辑控制。

适用场景：

  • 代码风格检查和自动格式化
  • 安全性验证和权限控制
  • 文件系统操作前的合法性检查
  • 环境变量的自动配置

实战案例：自动代码格式化

#!/bin/bash
# .claude/hooks/format-check.sh

# 检查文件是否是 Python 文件
if [[ "$CLAUDE_INPUT" == *.py ]]; then
    # 运行 Black 格式化
    black --check "$CLAUDE_INPUT"
    if [ $? -ne 0 ]; then
        echo "❌ 代码格式不符合 Black 标准"
        echo "🔧 正在自动格式化..."
        black "$CLAUDE_INPUT"
        echo "✅ 格式化完成"
    fi
fi

exit 0

2.2 基于提示的 Hooks：智能决策的大脑

基于提示的 Hooks 是 Claude Hooks 系统中最具创新性的特性，它利用 LLM（大语言模型）来评估复杂的上下文，做出智能决策。

核心优势：

  • 上下文感知：理解对话历史和任务上下文
  • 自然语言推理：用自然语言定义判断逻辑
  • 灵活性强：适应多变的场景和需求

适用场景：

  • 判断任务是否真正完成
  • 评估是否需要继续工作
  • 复杂权限的智能决策
  • 用户意图的理解和验证

实战案例：智能停止判断

{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {
            "type": "prompt",
            "prompt": "你正在评估 Claude 是否应该停止工作。\n\n上下文：$ARGUMENTS\n\n请分析：\n1. 用户要求的所有任务是否完成\n2. 是否存在需要修复的错误\n3. 是否需要后续的跟进工作\n\n返回 JSON 格式：\n{\"ok\": true} 允许停止\n{\"ok\": false, \"reason\": \"继续工作\"} 继续工作",
            "timeout": 30
          }
        ]
      }
    ]
  }
}

两种模式的对比：

特性 Bash 命令 Hooks 基于提示的 Hooks
执行方式 运行本地脚本 查询 LLM API
决策逻辑 确定性规则 上下文感知推理
设置复杂度 需要编写脚本 配置提示词
上下文理解 受限于脚本逻辑 自然语言理解
执行速度 快（本地执行） 较慢（API 调用）
最佳用途 确定性规则 智能决策判断

三、Claude Hooks 的核心事件体系

Claude Hooks 定义了丰富的生命周期事件，覆盖了从会话启动到结束的全过程。

3.1 工具执行事件

PreToolUse：工具执行前的守门人

  • 触发时机：在 Claude 创建工具参数之后、处理工具调用之前
  • 核心价值：控制工具调用、修改工具输入、权限管理
  • 常见用途：安全性验证、输入参数校验、敏感操作拦截

实战案例：防止删除重要文件

#!/bin/bash
# .claude/hooks/protect-important-files.sh

FILE_PATH=$(echo "$CLAUDE_INPUT" | jq -r '.file_path')

# 定义受保护的文件列表
PROTECTED_FILES=(
    "/etc/passwd"
    "/etc/hosts"
    "package-lock.json"
    "yarn.lock"
)

for protected in "${PROTECTED_FILES[@]}"; do
    if [[ "$FILE_PATH" == *"$protected"* ]]; then
        echo "❌ 错误：试图删除受保护文件"
        echo "📁 文件：$FILE_PATH"
        echo "🔒 此文件受 Hooks 保护，无法删除"
        exit 2  # 退出码 2 表示阻止操作
    fi
done

exit 0

PostToolUse：工具执行后的分析师

  • 触发时机：在工具成功完成后立即运行
  • 核心价值：执行后处理、结果验证、上下文增强
  • 常见用途：代码审查、日志记录、格式化、测试触发

3.2 权限管理事件

PermissionRequest：智能权限决策器

  • 触发时机：在向用户显示权限对话框时运行
  • 核心价值：代表用户自动允许或拒绝权限请求
  • 常见用途：自动批准安全操作、拦截高风险操作

3.3 会话生命周期事件

SessionStart：环境配置师

  • 触发时机：在 Claude Code 启动新会话或恢复现有会话时运行
  • 核心价值：自动加载开发上下文、配置环境、安装依赖
  • 触发类型：startup、resume、clear、compact

实战案例：自动环境配置

#!/bin/bash
# .claude/hooks/session-start.sh

# 激活 Python 虚拟环境
if [ -d "venv" ]; then
    source venv/bin/activate
    echo "✅ Python 虚拟环境已激活"
fi

# 检查并安装依赖
if [ -f "requirements.txt" ]; then
    pip install -q -r requirements.txt
    echo "✅ 依赖已安装"
fi

# 持久化环境变量
if [ -n "$CLAUDE_ENV_FILE" ]; then
    echo 'export PROJECT_ROOT=$(pwd)' >> "$CLAUDE_ENV_FILE"
    echo 'export PYTHONPATH=$PYTHONPATH:$(pwd)' >> "$CLAUDE_ENV_FILE"
fi

exit 0

SessionEnd：清理工程师

  • 触发时机：在 Claude Code 会话结束时运行
  • 核心价值：清理资源、记录统计、保存状态
  • 退出原因：clear、logout、prompt_input_exit、other

3.4 通知与交互事件

Notification：消息分发器

  • 触发时机：在 Claude Code 发送通知时运行
  • 常见通知类型：permission_prompt、idle_prompt、auth_success、elicitation_dialog

UserPromptSubmit：提示验证官

  • 触发时机：在用户提交提示时，在 Claude 处理之前运行
  • 核心价值：验证用户输入、添加额外上下文、阻止无效提示
  • 常见用途：提示词过滤、自动补充上下文、敏感内容检测

3.5 会话控制事件

Stop：智能停止判断

  • 触发时机：在主 Claude Code agent 完成响应时运行
  • 核心价值：判断任务是否真正完成，避免过早停止
  • 注意：如果停止是由于用户中断而发生的，则不运行

SubagentStop：子任务管理

  • 触发时机：在 Claude Code subagent（Task 工具调用）完成响应时运行
  • 核心价值：评估子任务是否完成，协调多个子任务

PreCompact：压缩前预检

  • 触发时机：在 Claude Code 即将运行压缩操作之前运行
  • 触发类型：manual（从 /compact 调用）、auto（从自动压缩调用）

四、Claude Hooks 的多层次配置

Claude Hooks 支持在多个层面进行配置，形成了一个灵活的多层次架构。

4.1 全局用户级 Hooks

配置文件：~/.claude/settings.json

特点：

  • 对所有项目和会话生效
  • 适用于个人编码规范和安全策略
  • 优先级低于项目和插件 Hooks

典型应用：

  • 全局代码风格检查
  • 个人安全策略
  • 常用工具的快捷配置

4.2 项目级 Hooks

配置文件：

  • .claude/settings.json（项目设置，可提交到版本控制）
  • .claude/settings.local.json（本地项目设置，不提交）

特点：

  • 仅对当前项目生效
  • 适用于项目特定的规范和工作流
  • 优先级高于用户级 Hooks

典型应用：

  • 项目特定的代码规范
  • 项目依赖的自动配置
  • 项目特定的工作流自动化

4.3 插件级 Hooks

配置文件：hooks/hooks.json（在插件目录下）

特点：

  • 与插件无缝集成
  • 插件启用时自动合并到配置
  • 支持多个插件 Hooks 响应同一事件

典型应用：

  • 第三方服务的集成
  • 特定技术栈的支持
  • 团队共享的 Hooks 库

实战案例：自动代码格式化插件

{
  "description": "Automatic code formatting plugin",
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [
          {
            "type": "command",
            "command": "${CLAUDE_PLUGIN_ROOT}/scripts/format.sh",
            "timeout": 30
          }
        ]
      }
    ]
  }
}

4.4 组件级 Hooks

支持组件：

  • Skills（技能）
  • Agents（代理）
  • Slash Commands（斜杠命令）

特点：

  • 仅在组件生命周期内运行
  • 组件执行完毕后自动清理
  • 支持 once 选项（每个会话只运行一次）

典型应用：

  • 特定技能的安全检查
  • 代理任务的事后处理
  • 命令执行的前置验证

实战案例：安全操作技能

---
name: secure-operations
description: 执行带安全检查的操作
hooks:
  PreToolUse:
    - matcher: "Bash"
      hooks:
        - type: command
          command: "./scripts/security-check.sh"
  once: true  # 每个会话只运行一次
---

4.5 Hooks 优先级和合并规则

当多个来源的 Hooks 响应同一事件时：

  1. 并行执行：所有匹配的 Hooks 同时运行
  2. 独立决策：每个 Hook 独立做出决策
  3. 结果合并：
    • 任一 Hook 阻止（退出码 2），操作被阻止
    • 所有 Hook 允许（退出码 0），操作继续
    • 输出按执行顺序叠加显示

五、Claude Hooks 的高级特性

5.1 结构化 JSON 输出

除了简单的退出码，Hooks 还可以通过 JSON 输出实现更复杂的控制。

通用 JSON 字段：

{
  "continue": true,
  "stopReason": "停止原因",
  "suppressOutput": true,
  "systemMessage": "系统警告消息"
}

5.2 PreToolUse 决策控制

PreToolUse Hooks 支持三种决策模式：

allow：自动允许

{
  "hookSpecificOutput": {
    "hookEventName": "PreToolUse",
    "permissionDecision": "allow",
    "permissionDecisionReason": "安全操作，自动允许"
  }
}

deny：拒绝执行

{
  "hookSpecificOutput": {
    "hookEventName": "PreToolUse",
    "permissionDecision": "deny",
    "permissionDecisionReason": "危险操作，已拦截"
  }
}

ask：询问用户

{
  "hookSpecificOutput": {
    "hookEventName": "PreToolUse",
    "permissionDecision": "ask",
    "permissionDecisionReason": "需要用户确认"
  }
}

updatedInput：修改工具输入

{
  "hookSpecificOutput": {
    "hookEventName": "PreToolUse",
    "permissionDecision": "allow",
    "updatedInput": {
      "command": "npm run lint -- --fix"
    }
  }
}

5.3 PostToolUse 决策控制

PostToolUse Hooks 可以为 Claude 提供反馈：

{
  "decision": "block",
  "reason": "代码存在安全问题，请修复",
  "hookSpecificOutput": {
    "hookEventName": "PostToolUse",
    "additionalContext": "建议使用参数化查询替代字符串拼接"
  }
}

5.4 UserPromptSubmit 上下文注入

UserPromptSubmit Hooks 可以向对话添加额外上下文：

方式一：纯文本输出（简单）

#!/bin/bash
echo "当前项目：E-commerce 平台"
echo "技术栈：React + Node.js + PostgreSQL"
echo "注意：生产环境部署前必须通过安全审查"
exit 0

方式二：JSON 结构化输出（高级）

{
  "hookSpecificOutput": {
    "hookEventName": "UserPromptSubmit",
    "additionalContext": "当前项目是金融级应用，所有代码变更必须通过安全审计"
  }
}

阻止提示：

{
  "decision": "block",
  "reason": "提示包含敏感词，已被阻止"
}

六、Claude Hooks 实战案例

6.1 案例一：企业级代码质量保障系统

背景：一家大型企业需要确保所有代码变更都符合公司规范。

解决方案：

1. PreToolUse Hook：代码审查前检查

#!/bin/bash
# .claude/hooks/pre-code-review.sh

# 检查是否是代码编辑操作
TOOL_NAME=$(echo "$CLAUDE_INPUT" | jq -r '.tool_name')

if [[ "$TOOL_NAME" == "Edit" || "$TOOL_NAME" == "Write" ]]; then
    FILE_PATH=$(echo "$CLAUDE_INPUT" | jq -r '.tool_input.file_path')
    
    # 检查文件是否在保护目录中
    if [[ "$FILE_PATH" == *"/production/"* ]]; then
        echo "⚠️  警告：正在修改生产环境代码"
        echo "📋 请确保已通过 Code Review 流程"
        echo "🔗 相关文档：https://wiki.company.com/code-review"
        
        # 不阻止，但给出警告
        exit 0
    fi
fi

exit 0

2. PostToolUse Hook：自动格式化和测试

#!/bin/bash
# .claude/hooks/post-code-check.sh

TOOL_NAME=$(echo "$CLAUDE_INPUT" | jq -r '.tool_name')

if [[ "$TOOL_NAME" == "Write" || "$TOOL_NAME" == "Edit" ]]; then
    FILE_PATH=$(echo "$CLAUDE_INPUT" | jq -r '.tool_input.file_path')
    
    # 自动格式化 Python 文件
    if [[ "$FILE_PATH" == *.py ]]; then
        echo "🔧 正在格式化 Python 文件..."
        black "$FILE_PATH"
        
        # 运行类型检查
        echo "🔍 正在进行类型检查..."
        mypy "$FILE_PATH"
    fi
    
    # 自动格式化 JavaScript/TypeScript 文件
    if [[ "$FILE_PATH" == *.js || "$FILE_PATH" == *.ts ]]; then
        echo "🔧 正在格式化 JavaScript/TypeScript 文件..."
        prettier --write "$FILE_PATH"
        
        # 运行 ESLint
        echo "🔍 正在运行 ESLint..."
        eslint "$FILE_PATH" --fix
    fi
fi

exit 0

效果：

  • ✅ 所有代码自动符合公司规范
  • ✅ 实时反馈代码质量问题
  • ✅ 减少人工审查负担

6.2 案例二：多环境智能部署系统

背景：一个需要同时在开发、测试、生产三个环境部署的系统。

解决方案：

#!/bin/bash
# .claude/hooks/smart-deploy.sh

# 从 Hook 输入中提取环境信息
ENV=$(echo "$CLAUDE_INPUT" | jq -r '.tool_input.environment')

case "$ENV" in
    "dev")
        echo "🔧 部署到开发环境"
        echo "⚠️  注意：开发环境数据可能在任何时刻被重置"
        ;;
    "staging")
        echo "🧪 部署到测试环境"
        echo "✅ 将运行完整的测试套件"
        
        # 运行测试
        npm test
        
        if [ $? -ne 0 ]; then
            echo "❌ 测试失败，部署中止"
            exit 2
        fi
        ;;
    "production")
        echo "🚀 部署到生产环境"
        echo "⚠️  警告：生产环境部署需要额外确认"
        echo "📋 请确保已通过所有审查流程"
        echo "🔗 回滚计划：https://ops.company.com/rollback/$CURRENT_VERSION"
        ;;
    *)
        echo "❌ 错误：未知环境 '$ENV'"
        echo "📋 可用环境：dev, staging, production"
        exit 2
        ;;
esac

exit 0

配置：

{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "deploy",
        "hooks": [
          {
            "type": "command",
            "command": "./.claude/hooks/smart-deploy.sh"
          }
        ]
      }
    ]
  }
}

效果：

  • ✅ 根据环境自动应用不同的策略
  • ✅ 测试环境自动运行测试
  • ✅ 生产环境提供安全警告和回滚方案

6.3 案例三：智能学习助手

背景：一个帮助学生学习编程的 AI 助手，需要根据学生进度调整难度。

解决方案：

{
  "hooks": {
    "UserPromptSubmit": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "./.claude/hooks/assess-student-level.sh"
          }
        ]
      }
    ],
    "Stop": [
      {
        "hooks": [
          {
            "type": "prompt",
            "prompt": "你正在评估一个编程学习会话是否应该结束。\n\n学生水平：${STUDENT_LEVEL}\n完成的任务数：${TASK_COUNT}\n正确率：${ACCURACY}\n\n请判断：\n1. 学生是否真正理解了当前概念\n2. 是否需要更多的练习\n3. 是否应该进入下一个难度级别\n\n返回 JSON：\n{\"ok\": true} 允许结束\n{\"ok\": false, \"reason\": \"原因\"} 继续学习"
          }
        ]
      }
    ]
  }
}

评估脚本：

#!/bin/bash
# .claude/hooks/assess-student-level.sh

# 从历史记录中分析学生水平
CORRECT_ANSWERS=$(grep "正确" ~/.claude/student_history.json | wc -l)
TOTAL_QUESTIONS=$(grep "问题" ~/.claude/student_history.json | wc -l)
ACCURACY=$((CORRECT_ANSWERS * 100 / TOTAL_QUESTIONS))

if [ "$ACCURACY" -gt 80 ]; then
    echo "学生当前水平：高级"
    echo "建议：可以进入下一阶段学习"
elif [ "$ACCURACY" -gt 60 ]; then
    echo "学生当前水平：中级"
    echo "建议：继续当前难度，增加练习"
else
    echo "学生当前水平：初级"
    echo "建议：降低难度，加强基础"
fi

# 将评估结果注入上下文
echo "STUDENT_LEVEL=$( [ "$ACCURACY" -gt 80 ] && echo "高级" || ([ "$ACCURACY" -gt 60 ] && echo "中级" || echo "初级" ))"
echo "TASK_COUNT=$TOTAL_QUESTIONS"
echo "ACCURACY=$ACCURACY%"

exit 0

效果：

  • ✅ 根据学生表现自动调整难度
  • ✅ 提供个性化的学习建议
  • ✅ 确保学生真正理解后再继续

七、Claude Hooks 最佳实践

7.1 Bash Hooks 最佳实践

1. 保持脚本简洁

  • 每个 Hook 只做一件事
  • 避免复杂的逻辑链
  • 优先使用标准工具

2. 正确使用退出码

  • 0：成功，继续执行
  • 2：阻止操作，显示错误
  • 其他：非阻止错误

3. 提供清晰的输出

  • 使用表情符号增强可读性
  • 输出应该简洁明确
  • 包含必要的上下文信息

4. 使用环境变量

echo "项目目录：$CLAUDE_PROJECT_DIR"
echo "插件根目录：${CLAUDE_PLUGIN_ROOT}"
echo "当前会话 ID：$CLAUDE_SESSION_ID"

7.2 基于提示的 Hooks 最佳实践

1. 明确提示词

  • 清楚说明要评估的内容
  • 提供具体的判断标准
  • 使用结构化的 JSON 响应格式

2. 设置合理的超时

{
  "timeout": 30  // 默认 30 秒，根据需要调整
}

3. 测试和迭代

  • 验证 LLM 的决策准确性
  • 根据实际效果调整提示词
  • 收集边界案例进行优化

4. 用于复杂决策

  • Bash Hooks 适合确定性规则
  • 提示 Hooks 适合需要上下文理解的场景

7.3 性能优化

1. 并行执行

  • 多个 Hooks 可以同时运行
  • 避免串行依赖的设计

2. 快速失败

  • 在 Hook 早期进行关键检查
  • 避免不必要的计算

3. 缓存结果

#!/bin/bash
CACHE_FILE="/tmp/claude-hook-cache.txt"

if [ -f "$CACHE_FILE" ]; then
    cat "$CACHE_FILE"
    exit 0
fi

# 执行计算
RESULT=$(expensive-computation)

# 缓存结果
echo "$RESULT" > "$CACHE_FILE"

echo "$RESULT"
exit 0

7.4 安全性考虑

1. 验证输入

#!/bin/bash
FILE_PATH=$(echo "$CLAUDE_INPUT" | jq -r '.file_path')

# 检查路径是否在允许的范围内
if [[ "$FILE_PATH" != "/allowed/path/"* ]]; then
    echo "❌ 错误：路径不在允许范围内"
    exit 2
fi

2. 避免代码注入

  • 使用 jq 安全解析 JSON
  • 避免直接执行用户输入
  • 使用绝对路径引用脚本

3. 最小权限原则

  • Hooks 只执行必要的操作
  • 避免使用 root 权限
  • 限制访问敏感资源

九、常见问题与解决方案

9.1 Hooks 不生效

问题：配置了 Hooks 但没有执行。

排查步骤：

  1. 检查配置文件路径是否正确
  2. 验证 JSON 格式是否有效
  3. 确认事件名称和匹配器是否正确
  4. 检查脚本是否有执行权限

解决方法：

# 添加执行权限
chmod +x .claude/hooks/*.sh

# 验证 JSON 格式
cat .claude/settings.json | jq '.'

# 测试 Hook 脚本
./.claude/hooks/test-hook.sh

9.2 Hooks 执行超时

问题：Hook 执行时间过长导致超时。

解决方法：

{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "*",
        "hooks": [
          {
            "type": "command",
            "command": "./script.sh",
            "timeout": 60  // 增加超时时间
          }
        ]
      }
    ]
  }
}

9.3 Hooks 互相干扰

问题：多个 Hooks 产生冲突的输出。

解决方法：

  • 使用 suppressOutput 控制输出
  • 明确每个 Hook 的职责
  • 使用 continue 字段控制执行流程

9.4 环境变量不可用

问题：Hook 中无法访问 CLAUDE_PROJECT_DIR 等环境变量。

解决方法：

#!/bin/bash
# 检查环境变量是否存在
if [ -z "$CLAUDE_PROJECT_DIR" ]; then
    echo "❌ 错误：CLAUDE_PROJECT_DIR 未设置"
    exit 2
fi

# 使用环境变量
cd "$CLAUDE_PROJECT_DIR"
